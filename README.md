# Эмулятор Яндекс Станции Мини 2 для macOS

Linux / Proxmox: [инструкция Linux-порта](README-LINUX.md).

Рабочий экспериментальный стенд: QEMU запускает настоящую ARM32-прошивку Мини 2
на Linux ARM64, веб-панель показывает консоль, сервисы, LED-кольцо и часы.
Снимок состояния от 23 октября 2026 года. Это **не завершённая замена колонки**:
привязка аккаунта из приложения пока не подтверждена.

## Быстрый запуск на Apple Silicon

Нужны macOS, Command Line Tools и Homebrew. Подготовьте около 3 ГБ свободного места.

```bash
git clone https://github.com/initialfox/yandex-station-emulator.git
cd yandex-station-emulator
bash setup_macos.sh
```

Скрипт установит QEMU и Python, проверит SHA256 всех частей комплекта, восстановит
готовый Linux/диск прошивки, проверит пару PEM, соберёт приложение мостов и
откроет панель на **http://127.0.0.1:8765/**. В macOS разрешите приложению
**Alice Hardware Bridge** Bluetooth и микрофон. Образы вручную искать не нужно.
Крупный runtime находится в `assets/runtime.tar.gz.part*`; Git LFS не требуется.
Существующий диск при повторном запуске установщика сохраняется.

Дальнейшие запуски:

```bash
bash qemu/mini2/run_stand.sh
```

## Что работает

| Часть | Проверенное состояние |
|---|---|
| Прошивка | `platformd`, `mediad`, `telemetry` запускаются в QEMU |
| Динамик | Алиса произносит штатные фразы, работает вывод через CoreAudio |
| Микрофон | Mac → PCM 48 кГц → гостевая ALSA → процесс Алисы; подтверждено чтение потока самим `platformd` |
| LED и часы | Значения настоящей прошивки через эмулированный sysfs; кольцо рисуется непрерывным свечением |
| Quasar PEM | Штатный клиент выполняет export/sign/decrypt; подпись и расшифрование проверены независимо |
| Интернет | NAT по умолчанию; прямой LAN-мост через Wi-Fi Mac также проверен |
| Панель | Консоль сразу видна, запуск/остановка/ребут, статусы сервисов |

## Что пока не работает / не доказано

- Приложение Яндекса **не обнаруживает** CoreBluetooth-мост. GATT читается и
  macOS подтверждает рекламу, но публичный API не позволяет воспроизвести
  Manufacturer Data настоящей колонки (`0x0905`, данные `04 4b`). Причина
  фильтрации приложением окончательно не доказана. Raw USB Bluetooth пока не проверен.
- Настройка **по звуку не завершена**. `sound_initd` слушает; пользователь
  проигрывал сигнал, но принятый настроечный пакет не появился. Раскладка каналов
  и обработка VQE требуют дальнейшей проверки. Не считать это успешной привязкой.
- Работа микрофонного транспорта не доказывает распознавание команд или доступ к аккаунту.
- В госте нет настоящего Wi-Fi-радио: LAN-мост даёт сеть через Wi-Fi Mac,
  а сканирование/подключение SSID внутри прошивки пока использует wired shim.
- Оригинальный аппаратный `keymaster` не восстановлен. В отдельном эксперименте
  OP-TEE и TA запускались, но оригинальный `unifykeys/key_blob` отсутствует.
  Основной стенд использует PEM-адаптер. Принимает ли эти ключи облако для
  текущей идентичности Mini 2, пока не установлено.
- Зелёные статусы загрузки и голосовое приветствие не означают готовность к onboarding.

## Подключение напрямую к локальной сети

```bash
sudo bash qemu/mini2/tools/enable_lan.sh
```

После сообщения `LAN bridge ready` нажмите «Перезагрузить» в панели. Привилегии
нужны только отдельному сетевому процессу vmnet. Основной QEMU остаётся от вашего
пользователя. Гость получит свой DHCP-адрес от роутера через `en0`; служебный
адаптер NAT отдельно доставляет микрофон с Mac. При смене аппаратного интерфейса
поменяйте `ifname=en0` в скрипте. Проверенный адрес в исходной сети был
`172.16.62.104`; в вашей сети он будет другим.

## Ключи и комплект

По явному указанию владельца переданные `keys/private.pem` и `keys/public.pem`
включены в этот репозиторий. Это одна конкретная пара RSA-2048, а не ключи,
создаваемые заново для каждой установки. Успешная локальная подпись не означает
успешную регистрацию устройства на сервере. Для своей пары замените эти два
файла или задайте `PEM_SOURCE_DIR=/absolute/path/to/keys` при запуске.

При загрузке файлы копируются в гостевой tmpfs с правами 0600. Временная копия
в bootstrap удаляется. После ребута они загружаются снова из `keys/`.
SSH-доступ к физической колонке, дампы аккаунта и посторонние файлы не включены.

## Как устроено

`qemu/mini2/start.sh` запускает `virt`, Cortex-A53, четыре CPU и 1 ГБ RAM.
Alpine bootstrap примонтирован через 9p; реальная прошивка лежит на отдельном
512-МБ ext4-диске. NV подключён только для чтения. ARM32-код работает через
совместимость ядра ARM64. GPIO 414/419 и LED sysfs предоставлены моделью стенда.
Обновляющая прошивку служба `updatesd` отключена в launch-конфигурации стенда.

Микрофон: `HardwareBridge.swift` → loopback TCP 19093 → `mic_relay.c` → ALSA.
BLE: CoreBluetooth → loopback HTTP 19092 → штатные GATT-объекты через D-Bus.
PEM: `optee/pem_proxy.c` реализует используемые export/sign/decrypt операции
сокета `keymaster_svc`; generate/upgrade не реализованы.

## Диагностика и остановка

```bash
curl http://127.0.0.1:8765/api/firmware
cat qemu/mini2/run/hardware.json
python3 qemu/mini2/tools/console.py 'ps | grep maind'
python3 qemu/mini2/tools/console.py 'tail -n 5 /mini2/tmp/mic-relay.log'
bash scripts/stop.sh
```

Основные журналы: `qemu/mini2/run/console.log`, `start.log`, `hardware-rpc.log`.
Внутри гостя: `/mini2/bkupgrade/data/quasar/daemons_logs/maind.log` и `.1`.
Статус `keymaster` в исходной панели относится к защищённой TEE-службе и может
показывать недоступность при работающем PEM-адаптере.

При переносе на другой Mac пересобирайте HardwareBridge через setup, чтобы macOS
запросила разрешения у локально собранного приложения. Intel Mac и другие ОС
этим комплектом не проверялись. Runtime содержит Alpine Linux и прошивку Яндекса;
права на сторонние компоненты остаются у их правообладателей.
